## [2026-06-29] — Сессия 2: деплой, отладка, доработки UX

### Добавлено
- Деплой на VPS (`/home/deploy/bots/booking-bot/`), systemd-сервис `booking-bot.service`
- Groq (llama-3.1-8b-instant) вместо dateparser для парсинга свободного текста — понимает "давай завтра в 10-30", "а в среду когда есть окна?", "на следующей неделе в 14:00"
- Поиск по диапазону недели: `date_range: next_week|current_week` + `target_hour` → показывает дни где нужный час свободен
- Уточняющий вопрос "до обеда или после?" при запросе дня без времени — с предварительной проверкой наличия слотов в каждой половине
- Напоминание за 5 минут до сессии со ссылкой на видеозвонок
- Ссылки на Jitsi Meet (уникальная per-запись: `meet.jit.si/georg-psych-{uuid}`)
- Telegram username клиента в описании события Google Calendar
- Таблица `clients` в SQLite — запоминаем клиентов, при повторной записи предлагаем сохранённые данные
- Согласие на обработку персональных данных (ФЗ-152) — запрашивается при первой записи
- Команда `/privacy` — политика конфиденциальности
- Команда `/deletedata` — удаление данных по запросу клиента
- Кнопка "📋 Мои записи" в главном меню
- Catch-all хендлер — любой текст вне FSM передаётся в Groq как запрос времени
- Обработка намерения отмены по ключевым словам ("отмени", "перенеси")
- Автоматическое предложение использовать TG @username вместо запроса номера телефона
- Контекстные сообщения при показе слотов ("На 30 июня свободных слотов нет. Вот ближайшие:")
- Кнопка "Записаться" возвращается после завершения флоу (успех/отмена)

### Исправлено
- `LANGUAGES` не является валидным ключом настроек dateparser — перенесён как параметр `languages=["ru"]`
- "30 june" вместо "30 июня" — заменён `strftime("%B")` на ручной словарь месяцев
- FSM-состояние сбрасывается после перезапуска (MemoryStorage) — задокументировано как ожидаемое поведение
- Rate limit dateparser/Groq: уменьшен с 10 до 4 секунд
- `timeRangeEmpty` от Google Calendar API когда `min_start > period_end` — добавлена проверка в `build_search_range`
- Groq не распознавал "завтра" без явного упоминания в промпте — добавлены явные правила "завтра → date=YYYY-MM-DD"
- Двойной `+` в номере телефона при использовании TG-кнопки "Поделиться номером"
- Catch-all хендлер перехватывал кнопки "Мои записи" и "/cancel" — перенесён в конец файла
- Groq возвращал `period: morning` для запросов с конкретным временем — при наличии `time` поле `period` игнорируется
- Миграция БД при деплое: добавлены колонки `meet_url`, `reminder_5min_sent`, `consent_given`, `consent_at`

### Изменено
- Парсинг дат: dateparser → Groq с препроцессором (стоп-слова, "10-30"→"10:30", "в 11"→"11:00")
- `date_parser.py`: возвращает `ParseResult` (TypedDict) вместо кортежа — добавлены поля `date_range` и `target_hour`
- Флоу контакта: убрана кнопка "Поделиться номером", добавлено автопредложение TG @username
- Уведомление психологу о новой записи дополнено ссылкой на Телемост

## [2026-06-29] — Полный первичный код бота

### Добавлено
- `bot.py` — точка входа, инициализация БД, polling, фоновый цикл напоминаний
- `config.py` — все настройки из .env (токен, Calendar ID, рабочие часы)
- `database.py` — SQLite через aiosqlite: создание/получение/отмена записей, напоминания
- `services/date_parser.py` — парсинг свободного текста (dateparser + словарь периодов дня)
- `services/slot_finder.py` — генерация и фильтрация слотов (9–17 МСК, начало часа, 55 мин)
- `services/calendar_service.py` — Google Calendar API через Service Account: freebusy + create + delete
- `services/notifier.py` — фоновый asyncio-цикл напоминаний за 24 ч и 1 ч до сессии
- `handlers/booking.py` — полный FSM-флоу: время → слот → имя → контакт → подтверждение → Calendar
- `handlers/admin.py` — /bookings, подтверждение/отклонение нестандартных запросов
- `tests/test_slot_finder.py` — 7 тестов генерации и фильтрации слотов
- `tests/test_date_parser.py` — 8 тестов парсинга дат и периодов
